# Fog of War — план разработки

Многопользовательская Android-игра: танки в тумане войны, 1–6 игроков по локальной сети
через **Google Play Services Nearby Connections**. Управление: джойстик + кнопка огня.
Виден только узкий луч фары перед танком; раз в несколько секунд из центра карты идёт
сонар, подсвечивающий врагов красными точками. 3 HP, сужающаяся зона, 4 большие карты.
Побеждает последний выживший.

---

## 1. Технологический стек

* **Язык:** Kotlin.
* **UI:** классические View + XML (меню, лобби), игровой рендер — нативный `SurfaceView` + `Canvas`
  (без Unity/LibGDX, APK ~5–10 МБ, быстрая сборка в CI).
* **Сеть:** Google Play Services Nearby Connections, `Strategy.P2P_STAR` (хост + до 5 клиентов).
* **Протокол:** компактный бинарный формат на `ByteBuffer` (низкая задержка, без лишних зависимостей).
* **Сборка:** Gradle (Kotlin DSL), AGP 8.5.2, Kotlin 1.9.24, compileSdk 34, minSdk 26.
* **CI:** GitHub Actions собирает подписанный APK на каждый пуш и публикует артефакт/релиз.

## 2. Модули

### 2.1 Сетевой слой и постоянное лобби (`network`, `lobby`)
* Топология «звезда»: хост создаёт комнату, остальные подключаются к нему.
* `NearbyNet` — синглтон на уровне `Application`, не привязан к экрану: соединение
  переживает переходы меню ↔ лобби ↔ игра, поэтому заново подключаться к комнате
  между раундами не нужно.
* Состояния комнаты: `LOBBY` → `IN_GAME` → `ROUND_OVER` → `LOBBY` по тем же `endpointId`.
* Никнейм хранится в `SharedPreferences`, передаётся хосту в `Hello`, хост рассылает актуальный
  состав лобби (`Roster`: id, ник, победы, готовность).
* Хост выбирает карту и запускает раунд; клиенты видят выбор и таймер старта.

### 2.2 Авторитетный хост и игровой цикл (`engine`, `protocol`)
* Всю физику, попадания, урон зоны, таймер сонара и сужение зоны считает **хост**
  с фиксированным тикрейтом 30 TPS.
* Клиенты отправляют только `Input` (направление джойстика + флаг огня / seq).
* Хост рассылает `Snapshot` 30 Гц: танки, пули, радиус зоны, радиус волны сонара,
  список только что разрушенных кирпичей. Клиент интерполирует позиции с задержкой ~100 мс.
* Одиночная игра: хост при старте без клиентов спавнит до 5 простых ботов
  (`BotController`: едут к центру/безопасной зоне, стреляют по видимой цели).

### 2.3 Карты и физика (`map`)
* Тайловая сетка 64×64, тайл 32 мировые единицы (карта 2048×2048).
* Тайлы: `EMPTY`, `BRICK` (разрушаемый, 2 попадания), `STEEL` (неразрушимый), `WATER`
  (непроходим для танка, прозрачен для пуль и света).
* 4 карты, генерируются детерминированно по `(mapId, seed)`, seed передаётся в `StartRound`,
  поэтому вся карта по сети не гоняется:
  1. «Лабиринт Руин» — кирпичные кварталы и узкие улицы;
  2. «Стальная Крепость» — коридоры из стали, открытый центр;
  3. «Мосты» — реки/вода и узкие перешейки;
  4. «Арена Колонн» — симметричные стальные колонны и укрытия.
* До 6 точек спавна по периметру. Коллизии танка — AABB с раздельным разрешением по осям.

### 2.4 Туман войны, фара и сонар (`render`)
* Рендер слоями:
  1. Мир: тайлы, танки, пули, граница зоны.
  2. Туман: почти чёрный слой на `saveLayer`, из него вырезается (`PorterDuff.CLEAR`)
     сектор фары перед танком (raycast по тайлам, ~40 лучей, стены и кирпич держат свет)
     плюс маленький круг вокруг своего танка. Враг виден только если попал в свет.
  3. Сонар: кольцо из центра карты каждые ~6 с рисуется поверх тумана; враги, через
     которых прошла волна и которые находятся в пределах экрана, вспыхивают красной
     точкой с затуханием ~1.2 с.
  4. HUD: 3 HP, число живых, джойстик, кнопка огня, стрелка к центру зоны.
* Камера следует за своим танком, зум подбирается под высоту экрана (~14 тайлов).

### 2.5 Сужающаяся зона и здоровье (`gameplay`)
* 3 HP, попадание = 1 HP + 0.5 с неуязвимости, при 0 — взрыв и режим наблюдателя.
* Круг зоны уменьшается от полной карты до маленького пятачка; вне зоны — 1 HP раз в 3 с.
* Победа — последний выживший.

### 2.6 CI/CD и обновляемый APK (`.github/workflows/android.yml`)
* **Единый ключ подписи:** `keystore/release.p12` в репозитории (PKCS12, создан openssl),
  параметры в `app/build.gradle.kts`; можно переопределить через GitHub Secrets.
* **Монотонный `versionCode`:** `1000 + GITHUB_RUN_NUMBER` → APK всегда ставится поверх
  предыдущего без `INSTALL_FAILED_UPDATE_INCOMPATIBLE`.
* Workflow: JDK 17 → `assembleRelease` → `unit test` → upload-artifact `fog-of-war.apk`.

## 3. Этапы

1. Gradle-проект, CI, единая подпись, versionCode.
2. Ядро: модели, 4 карты, физика, стрельба, урон, зона, боты.
3. Рендер: камера, туман + фара (raycast), сонар и блипы, HUD/джойстик.
4. Nearby Connections, никнеймы, постоянное лобби, хост-авторитетная синхронизация.

## 4. Правила для агентов

* `core/` не должен зависеть от Android API — на нём держатся JVM-unit-тесты.
* Сетевые сообщения меняются только вместе с обеими сторонами (Host и Client).
* Не повышать `versionCode` вручную — им управляет CI.
* Проверка сборки: `gh run watch` после `git push` (локально Android SDK нет).
